# Attendance access policy (replaces temporary setup mode)

Anyone can open the Android app or web portal from any location. Sign-in, email verification, HR approval, profile matching, device binding and role permissions still apply. Opening or resuming the app does not request location or watch venue boundaries.

Self-attendance requires an open event dated today in India time, the approved account's phone passkey, a fresh accurate position within the configured venue radius, and the Android phone connected to `Shikshavertex_5G`. The native submission uses that active connection and does not fall back to mobile data. The server independently validates the submitted location and fresh native connection observation. The default venue remains 12.912773610440954, 77.62322878099566, radius 100 m and maximum reported accuracy 50 m; distance plus uncertainty must fit within the radius. This checks building proximity, not a particular floor. SSID observations are not router attestation; optional BSSID and trusted public egress IP restrictions remain available.

Room codes are no longer used. The public policy reports `attendanceMode: onsite`, `accessRequired: false`, `locationRequired: true`, `attendanceWifi.required: true` and `requiresRoomCode: false`. Former `ENFORCE_ONSITE_ATTENDANCE` and `REQUIRE_ROOM_CODE` values are retired and cannot disable the new policy. Remove those obsolete variables when convenient; no change to signing fingerprints or authentication credentials is needed.

The app labels the prerequisite as the office connection. Browsers cannot observe its SSID and therefore cannot submit attendance or manual overrides. Employees use Android for check-in; HR can manage sessions and approvals and authorized viewers can inspect attendance from a computer anywhere. Native manual requests still require the operator's venue location and office connection; that operator location does not prove the target employee's presence and is stored separately in the audit record.

Historic setup-mode records are preserved as historical location-unverified records. New self check-ins use onsite evidence. Daily movement sharing remains separate and requires explicit consent; opening the app or marking attendance does not start sharing.

Deploy the updated server and web interface and install a signed Android 1.8 build using the existing pinned release key. Previously downloaded APKs retain their previous access behavior. Use [Android signing setup](android-signing-setup.md) and [physical-phone validation](phone-validation.md). Never install the unsigned setup candidate directly.
